## 一句话描述

数据已够 12 个月，把回测从「只有 3 个月」扩到 6m/12m；2w/4w 作为短周期观察档**单独评估**，不是"补不了才降级"。

## 背景

用户反馈：回测周期只有 3 个月，问能不能拉历史，或至少改成 2 周 / 4 周 / 12 周。

**数据侧事实（已核实，不必重查）**：

| 项 | 值 |
|----|----|
| 回补覆盖 | **2025-11-03 ~ 2026-11-03，243 个交易日** |
| 回补标的 | 7,180 只（个股 5,569 + 非债券 ETF 1,611），**0 失败、0 空数据** |
| 可用性分层 | ≥240 日 **6,453 只**；120~239 日 434 只；60~119 日 148 只；<60 日 145 只 |
| 现网 3m 实际区间 | 2026-08-04 ~ 2026-11-03（60 个交易日） |
| 扩档方案 | p1 附录 B 推荐 **A**：固定底座 `2025-10-31~2026-06-05` + archive 拼接 |
| 底座体积 | raw **315KB** / gzip **128KB**；产物 62KB（现网 68KB）/ gzip 8.4KB（现网 9KB） |
| 构建耗时 | 约 **2 秒**；与每日 Actions 完全兼容，无需常驻服务 |
| 缓存 | 95MB 仅本地、未入库；扩档需把**底座产物**入库（或在仓库内另择载体），不是把 95MB 入库 |
| 12m 余量 | 243 日距 240 门槛仅 3 天；建议 ETF 底座也补到 `2025-10-31`（约 5.5 分钟）→ 244 日，口径统一 |
| 硬约束 | 底座与 archive **必须统一复权口径**；禁止 qfq 与比率复权混拼（会在拼接处产生断层） |

**成本与风险判断**：

- 体积几乎不增（摘要字段数与档位无关，扩档只多算窗口）；
- 真正的风险是**复权拼接断层**与**底座入库载体**，不是算力；
- 池仍保持 59 只（ETF 29 + 个股 30），不做全市场预计算（附录 B 方案 B 已否）。

**2w/4w 单独评估**：

- 条件单是**短持仓策略（最长 5 个交易日）**，2 周/4 周窗口确实更贴近它的真实使用节奏，有产品价值；
- 但门槛低 → 交易笔数可能只有 0~2 笔，胜率没有统计意义；必须显示笔数并标注"样本不足"；
- 前端 `WindowKey` 目前只有 `3m/6m/12m`，新增 2w/4w 需改类型、静态兜底、构建脚本与文案，属额外工时；
- 结论：**作为可选增强**（P2），不塞进 26.11.1；先由 6m/12m 满足"能拉历史"的主要诉求。

## 验收标准（粗）

1. 6m/12m 两档在池内多数标的可用，页面显示实际区间与样本交易日数；
2. 底座入库（raw ≤ 315KB / gzip ≤ 128KB），产物体积不超现有预算（索引 ≤ 150KB、单摘要 ≤ 20KB）；
3. 构建 ≤ 5s，Actions 每日重建不超时、不新增常驻服务；
4. 底座与 archive 统一复权口径，拼接处无异常断层（抽查 ≥ 5 只）；
5. 3m 结果与现网**完全一致**（回归）；
6. 个标的样本不足时，该档置灰"该标的样本不足"，不得用更短数据冒充 6m/12m；
7. 2w/4w 仅在用户拍板后实现，且必须显示笔数与"样本不足"标注。
