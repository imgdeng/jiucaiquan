# us-116 · 回测标的口径改为"数据全量"— 需求文档

> 负责人：产品马 | 日期：2026-11-06 | 阶段：需求 | 优先级：P1（线上缺陷热修） | 迭代：26.11.1 热修

---

## 1. 缺陷定义

| 项 | 内容 |
|----|------|
| 标题 | 非头部标的被成交额排名挡在池外，搜索显示"暂未覆盖" |
| 级别 | **P1（线上功能缺陷）** |
| 影响 | 有行情数据的标的无法检索、无法回测，用户预期"搜索即能找到"被破坏 |
| 版本 | 26.11.1 已发布版本 |

### 复现步骤

1. 打开 `/tools/backtest`；
2. 在标的选择框输入 `512170`；
3. 观察结果列表与提示。

### 期望 vs 实际

| | 内容 |
|---|---|
| **期望** | 出现 `512170 医疗ETF`，可选中并展示该档回测摘要（或该档"数据不足"提示） |
| **实际** | 提示"暂未覆盖"，无法选中 |

### 根因

标的池构建时先取"末日成交额前 30 ETF + 前 30 个股"，再生成摘要；`512170` 未进入前 30，**在数据检查之前即被剔除**。排名承担了"准入"职责，而非"排序"职责。

## 2. 修复口径（用户硬约束）

> **宁可回测数据不全，不能标的不全。**

| # | 规则 |
|---|------|
| R1 | 可检索集合 = **数据侧实际有行情的全部标的**（以 data 为准）；成交额只决定默认排序与首屏列表，**不决定是否可被搜到** |
| R2 | 某标的某档历史不足时，标的**不得从池/索引中消失**；该档显示 `该标的此区间数据不足（可用 N 个交易日）`；档位按钮不可用按现有规则不渲染，但标的始终可检视 |
| R3 | 无结果提示只能是 `该标的本期无行情数据`，且仅当该代码确实无任何行情时出现；**删除"暂未覆盖"**这一用于"有数据但被排名挡掉"的表述 |
| R4 | 本卡为**已上线版本的缺陷修复**，走热修（patch），不等 26.11.2 |

### 规模与分层（已回填）

- 有行情标的全集数量：**7,180 只**（ETF 1,611 + 个股 5,569，均为 archive 中有行情标的）；
- 索引体积上限：raw ≤ 300KB / gzip ≤ 80KB（全量 code+name+成交额，不含逐笔明细）。
- **六档数字全量产出**：7,180 只 × `2w/4w/3m/6m/9m/12m`（10/20/60/120/180/240 日）；
- **逐笔与权益曲线只覆盖成交额前 300 只**；非前 300 标的明细区必须显示 `该标的逐笔明细暂仅对成交额前 300 只提供`，不得空白、不得显示 0。

| 层 | 覆盖 | 说明 |
|----|------|------|
| 可检索 universe | 7,180 只 | 搜索/选中/六档数字均可查 |
| 六档数字摘要 | 7,180 只 | 按标的按需加载 |
| 逐笔 + 权益曲线 | 成交额前 300 只 | 其余显示定位文案 |

已知代价（用户已接受）：库内底座一次性约 **39.6MB**（静态不增长）；summary 全量后每日仓库增量约 **7~9MB**。

## 3. 验收标准（AC）

| 编号 | 验收标准（选择器/数据可断言） | 责任 | 节点 |
|------|---------------------------|------|------|
| **AC-1** | `index.json` 的 `symbols` 集合与数据侧"有行情标的"全集逐代码比对：差集为空、总数 = **7,180**（ETF 1,611 + 个股 5,569）；`512170` 必在其中 | 工程马 → 项目马 | 热修验收 |
| **AC-2** | 搜索 `512170` 返回 1 条结果，DOM 含 `[data-symbol="512170"]`，展示代码 + 名称（医疗ETF）；全文不出现"暂未覆盖" | 工程马 | 热修验收 |
| **AC-3** | 选中 `512170` 后默认档可出摘要：胜率/收益率/最大回撤/区间/笔数 5 项齐全；切换任一可用档成功且数字随档变化 | 工程马 | 热修验收 |
| **AC-4** | 档位不足用例：`长鑫科技` 在 `6m/9m/12m` 显示 `该标的此区间数据不足（可用 66 个交易日）`；标的仍可被搜索/选中，其他档仍可切；不出现 0 值或空白卡 | 工程马 | 热修验收 |
| **AC-5** | 输入确定不存在的代码（如 `999999`）显示 `该标的本期无行情数据`；`512170` 在任何操作下均不得出现该提示 | 工程马 | 热修验收 |
| **AC-6** | 默认列表前 20 项按末日成交额降序，与 `leaderboard.json` 排序一致；搜索结果不受排名限制（`512170`、`512170` 之外的尾部标的均可命中）；排序字段有 `data-sort="turnover"`（或等价可断言标记） | 工程马 | 热修验收 |
| **AC-7** | 全量索引 raw ≤ 300KB / gzip ≤ 80KB；首屏 <3s；搜索输入到结果 ≤300ms；仍为纯静态、无新增请求类型/服务 | 工程马 | 热修验收 |
| **AC-8** | 合规不变：全文无 `热门/推荐/牛股/必涨/稳赚`；默认排序旁有 `按末日成交额排序，仅代表成交活跃度，不构成推荐`；"历史表现不代表未来收益"与"未计佣金与滑点"仍可见 | 产品马自检 → 项目马 | 热修验收 |
| **AC-9** | 回归：既有 59 只标的的 3m 胜率/收益率/最大回撤与线上 JSON 0 误差；us-113 五档覆盖文案与"数据不足"文案不变 | 工程马 | 热修验收 |
| **AC-10** | 若 us-114 A 概览的统计样本随全集扩大，页面显示的样本数必须等于实际参与统计的标的数（不得仍写 59）；分布数字与产物一致 | 工程马 + 产品马 | 热修验收 |
| **AC-11** | `512170` 六档数字全可用：`2w` 10 日、`4w` 20 日、`3m` 60 日、`6m` 120 日、`9m` 180 日、`12m` 240 日，各档显示实际区间与样本数；切换六档均能出摘要，无"数据不足" | 工程马 | 热修验收 |
| **AC-12** | 取默认排序 `rank > 300` 的第一只标的：明细区显示 `该标的逐笔明细暂仅对成交额前 300 只提供`，不得空白/0；同标的六档数字摘要仍正常展示与切换 | 工程马 + 产品马 | 热修验收 |

## 6. 风险

| 风险 | 应对 |
|------|------|
| 全量摘要体积膨胀 | 索引只含 code/name/成交额；六档摘要按标的按需加载；明细仅前 300 |
| 仓库日增 7~9MB | 用户已接受；底座 39.6MB 一次性入库、静态不增长 |
| 构建时间随 7,180 只增长 | 先测构建时长；超 5 分钟则拆卡同批上线 |
| 构建时间超 5 分钟 | 先测 `{{UNIVERSE_COUNT}}` 规模；超限则拆数据/前端两卡同批上线 |
| 全量含债券/货币 ETF 引发口径疑问 | 本卡按数据全量，不设品种准入；页面不推荐、不排序背书 |
| 搜索命中过多影响可用性 | 输入 ≥4 位才展示结果，默认仍显示成交额首屏；不改变空搜索观感 |
| 旧"暂未覆盖"文案残留 | AC-2 全文断言，构建后扫描 0 命中 |

## 7. 合规

- 全量可搜不等于推荐：排序说明必须写"仅代表成交活跃度，不构成推荐"；
- 不按收益率排序（TOP10 仅存在于 us-114 内测页）；
- 保留"历史表现不代表未来收益"与"未计佣金与滑点"；
- 不出现 `热门/推荐/必涨/牛股/稳赚`。
