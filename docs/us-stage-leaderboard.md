## 1. 背景与问题

韭菜圈自 2026 年 6 月上线以来，已积累 65 个交易日、5500+ 只 A 股、1600+ 只 ETF 的每日行情快照。但当前站点没有任何"回看一段时间"的能力：

- 读者无法快速回答"最近 3 个月哪个板块/个股/ETF 涨得最好"；

- 想看清市场主线，必须自己开行情软件逐只翻看，门槛高；

- 数据已沉淀但无产品化出口，数据资产闲置。

对 3 个月历史数据的离线分析已验证结论具备可读性（例：近 3 月创新药板块中位 +23%、艾艾精工 +206% 居个股榜首、卫星 ETF -19.8% 垫底），适合以"榜单"形态直接呈现给读者。

## 2. 用户故事

> **作为** 韭菜圈的读者（普通散户），
> **我希望** 在首页点一下就能看到"最近这段时间，哪些个股 / ETF / 板块涨得最好、跌得最惨"，并能切换时间范围与品类，
> **以便** 不用打开行情软件、不用自己计算，30 秒内看清当前市场主线，并对照自己的持仓表现。

## 3. 目标与非目标

### 3.1 目标

- 首页提供一张可交互的「阶段排行榜」卡片，覆盖**个股 / ETF / 板块**三类对象；

- 支持 **近1周 / 近1月 / 近3月 / 今年来** 四个区间切换、涨幅/跌幅双向排名；

- 所有切换即时响应（无刷新、无等待感）；

- 数据随每日行情任务自动更新，零人工维护；

- 数值准确，无份额折算/除权导致的假跌幅。

### 3.2 非目标（v1 不做）

- 自定义起止日期；

- 自选股 / 登录态 / 个人持仓对照；

- 个股或 ETF 详情页；

- 回测、策略信号、资金流向；

- K 线图 / sparkline 迷你走势（可留 v2）；

- 排行榜分享海报（可留 v2）。

## 4. 用户场景与验收标准

### 场景 1：默认浏览

- **Given** 读者打开韭菜圈首页，

- **When** 页面加载完成，

- **Then** 「阶段排行榜」卡片默认展示 **近 3 个月 · ETF · 涨幅榜 TOP 10**，每行显示排名、名称、代码、区间涨幅（红涨绿跌）、末日成交额。

### 场景 2：切换品类

- **Given** 读者正在看 ETF 榜，

- **When** 点击「个股」Tab，

- **Then** 榜单即时切换为个股涨幅 TOP 10（≤300ms，无页面刷新）。

### 场景 3：切换区间

- **Given** 读者正在看「近3月」榜，

- **When** 点击「近1周」，

- **Then** 榜单即时按近 5 个交易日的区间收益率重排。

### 场景 4：看跌幅榜

- **Given** 读者正在看涨幅榜，

- **When** 点击「跌幅榜」开关，

- **Then** 榜单按区间收益率升序排列（跌得最多在前），涨跌幅配色保持红涨绿跌。

### 场景 5：看板块主线

- **Given** 读者想知道近期市场主线，

- **When** 切换到「板块」Tab，

- **Then** 展示行业板块排名（以行业 ETF 聚合：板块中位涨幅 + 成交额最大的代表 ETF 名称与涨幅）。

### 场景 6：移动端浏览

- **Given** 读者在手机浏览器打开站点，

- **When** 浏览排行榜卡片，

- **Then** 卡片单列自适应，Tab/开关可点按，榜单可纵向滚动，无横向溢出。

### 场景 7：数据自动更新

- **Given** 每日行情数据任务（GitHub Actions）执行完成，

- **When** 次日读者访问站点，

- **Then** 榜单反映最新交易日数据，无需任何人工操作。

## 5. 功能需求详述

### 5.1 模块入口与默认态

- 位置：首页信息流中新增卡片「阶段排行榜」（具体位置由设计定，建议首屏内）；

- 默认选中：品类 = ETF，区间 = 近3月，方向 = 涨幅榜；

- 榜单行数：TOP 10（v1 不分页、不"查看更多"）。

### 5.2 筛选项

| 筛选项      | 选项                    | 说明                                           |
| -------- | --------------------- | -------------------------------------------- |
| 品类 Tab   | 个股 / ETF / 板块         | 三者互斥                                         |
| 区间 Chips | 近1周 / 近1月 / 近3月 / 今年来 | 近1周=5 个交易日，近1月=20 个，近3月=60 个；今年来 = 当年首个交易日至今 |
| 方向开关     | 涨幅榜 / 跌幅榜             | 涨幅降序 / 跌幅降序（即收益率升序）                          |

### 5.3 榜单行内容

- 个股 / ETF：排名序号、名称、代码、区间涨幅（%，保留 1 位小数，红涨绿跌）、末日成交额（亿元，保留 1 位）；

- 板块：排名序号、板块名、板块中位涨幅、代表 ETF 名称及其涨幅；

- 名称过长时省略号处理，代码小字灰色。

### 5.4 交互细节

- 所有筛选为**前端即时计算/排序**，不发起网络请求、不刷新页面；

- 切换时有轻微高亮过渡（设计把控，≤200ms）；

- 涨跌幅配色遵循 A 股习惯：红 = 涨，绿 = 跌；

- 无数据组合（如"今年来"在年初数据不足时）：展示空态文案"数据积累中"，不展示空白或报错。

## 6. 数据与技术方案（研发备注）

### 6.1 现状

- 每日行情由现有 GitHub Actions（`.github/workflows/market-data.yml`）抓取并归档至 `apps/web/public/data/archive/YYYY-MM-DD/{stock,etf}-latest.json`；

- 快照字段：`code / name / latest / open / high / low / close / changePct / amount / snapshotAt`；

- 注意：`latest` 为当日收盘快照价（`close` 字段实为昨收），收益率一律以 `latest` 计算。

### 6.2 方案：构建时预计算，前端零计算

1. 在每日数据构建流程（`services/market-data/`）中新增一步 `build_leaderboard.py`：

   - 读取全部历史归档；

   - 对每只标的复权修正后，计算 1 周 / 1 月 / 3 月 / 今年来四个窗口的区间收益率；

   - 聚合成板块榜；

   - 输出单个静态文件 `apps/web/public/data/leaderboard.json`（预计 gzip 后 \~100KB 量级）。
2. 前端卡片加载该 JSON，切换筛选时只做内存中的 filter + sort——这是"点击即出结果、≤300ms"的关键。**禁止**让浏览器拉取几十个日频文件现算。

### 6.3 leaderboard.json 建议结构

```json
{
  "generatedAt": "2026-09-04T20:05:00+08:00",
  "latestDate": "2026-09-04",
  "stocks": [
    { "code": "sh603580", "name": "艾艾精工", "ret1w": 0.052, "ret1m": 0.31,
      "ret3m": 2.055, "retYtd": 2.10, "amount": 3.2e8 }
  ],
  "etfs": [ /* 同上结构 */ ],
  "sectors": [
    { "name": "医药医疗", "ret3m": 0.233, "repCode": "sh513120",
      "repName": "港股创新药ETF广发", "repRet3m": 0.334, "count": 53 }
  ]
}
```

### 6.4 复权规则（关键坑，必须实现）

相邻快照日收益率超过涨跌幅限制时，判定为基金份额折算 / 个股除权除息，按比例向前修正历史价格：

| 对象                    | 涨跌幅限制 |
| --------------------- | ----- |
| 主板股票                  | 10%   |
| 创业板（300/301）、科创板（688） | 20%   |
| 北交所（8/4 开头）           | 30%   |
| 普通 ETF                | 10%   |
| 名称含"科创/创业"的 ETF       | 20%   |

- 判断时加 2% 容差，并考虑跨非交易日的间隔天数（复利上限）；

- 已验证：历史数据中 48 次 ETF 折算、260 次个股除权可被该规则正确识别；

- 复权逻辑在本次 3 个月数据分析中已跑通验证，可直接复用。

### 6.5 板块聚合规则

- 以行业/主题 ETF 为板块代理（个股无行业字段，ETF 名称含主题关键词）；

- 关键词映射表维护在构建脚本中（如：医药医疗 = \[医药, 医疗, 生物, 创新药, 中药…]），v1 覆盖约 15\~18 个板块；

- 板块涨幅 = 板块内合格 ETF（日均成交额 > 5000 万）区间涨幅的中位数；

- 代表 ETF = 板块内日均成交额最大者；

- 债券/货币类 ETF（名称含"债/货币/理财/短融"等）不参与任何榜单。

### 6.6 入榜过滤

- 区间起点或终点缺价（新上市/长期停牌）：剔除；

- 末日成交额：个股 < 1000 万、ETF < 2000 万：剔除（防僵尸标的占位）。

## 7. 边界与异常

| 情况                        | 处理                                      |
| ------------------------- | --------------------------------------- |
| 区间数据不足（如上线不满 3 个月时的"近3月"） | 以最早可用日为起点计算，并在卡片角标注明实际起始日；"今年来"无数据时展示空态 |
| 标的当日停牌                    | 沿用上一交易日价格                               |
| JSON 加载失败                 | 卡片整体降级隐藏，不影响首页其他模块；上报错误埋点               |
| 名称/代码缺失                   | 构建时过滤，不进入产物                             |

## 8. 埋点与度量

- 复用现有 `functions/api/track.ts` 接口；

- 事件：`leaderboard_view`（模块曝光）、`leaderboard_tab`（品类切换，带 tab 值）、`leaderboard_range`（区间切换）、`leaderboard_direction`（涨跌切换）；

- 成功度量：模块曝光点击率、各 Tab 切换分布（验证"板块"是否为读者最爱）；

- 数据质量度量：构建任务每日成功、复权事件数异常波动告警（v2 可做）。
